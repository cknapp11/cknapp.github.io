SSL (Secure Sockets Layer)

Secure Sockets Layer (SSL) is an Internet security protocol that encrypts data to ensure secure communication between devices over a network and was developed by Netscape in 1995 (GeeksforGeeks). Before SSL, web data was transmitted in plain text, making it vulnerable to interception and tampering. SSL solves this issue by encrypting sensitive information, autheniticating web servers, and ensuring data integrity uwing three mechanisms to ensure secure communication: encryption, authentication, and integrity.

  • Encryption: prevents unautherized parties from reading the data being transmitted, presenting itself as jumbled letters and numbers.
  • Authentication: uses the handshake method to verify the identity of the parties involved in the communication. The handskae method follows 4 steps: the client and server exchange hello messages, the server sends its digital certificate and server key information to the client, the client verifies the certificate and responds with its own, and lastly, Change Cipher Spec secures the connection.
  • Integrity: detects any tampering during transmission.

SSL Protocols

SSL features several different protocols that work for different purposes in securing online communication (GeeksforGeeks).

  • SSL Record Protocol: Secures transmission between the client and server. Data is broken into fragments and compressed with a message authentication code (MAC) to ensure integrity. The data is then encrypted and sent to the other party.
  • SSL Handshake Protocol: Follows a four-step process to establish a secure connection between the client and server. First, the client and server exchange hello messages. Next, the server sends its digital certificate and server key information to the client. Then, the client verifies the certificate and responds with its own. Finally, Change Cipher Spec secures the connection.
  • SSL Change-Cipher Spec Protocol: Signals to the other party that the pending cryptographic parameters have been received and processed.
  • SSL Alert Protocol: Gives the client and server a way to communicate errors and warnings during the communication process with two levels. The first is Warning Alerts, which alert that certificates are expired or not supported. These warnings are not critical and the connection can continue. The second is Fatal Alerts, which alert that the connection has been terminated due to a serious error. These include handshake failures, bad record MAC, and illegal parameters.

SSL Certificates

SSL certiciates, issued by trusted Certificate Authorities (CAs), are used to verify and secure websites (GeeksforGeeks). There exists three types of SSL certificates, as well as three SSL validation levels.

  • Single Domain SSL Certificate: Secures a single domain (e.g., www.example.com).
  • Multi-Domain SSL Certificate: Secures multiple domains with a single certificate.
  • Wildcard SSL Certificate: Secures a domain and its subdomains (e.g., *.example.com).
  • Domain Validation (DV): Validates the domain ownership and is the most basic level of validation.
  • Organization Validation (OV): Validates the organization behind the domain, providing a higher level of trust.
  • Extended Validation (EV): Provides the highest level of validation, requiring a thorough vetting process of the organization.

Transport Layer Security (TLS)

Transport Layer Security (TLS) is the successor to SSL, developed in 1999 to provide enhanced security at the transport layer. TLS ensures that no third-parties may intercept or modify the data being transmitted while building on all the security features of SSL making it the more secure option. TLS uses an advances version of the Handshake Protocol that uses the following (GeeksforGeeks):

  • Client Hello: Client starts the connection and sends its SSL/TLS version, cipher suites, and compression methods.
  • Server Selection: The server then checks for compatible SSL/TLS versions, cipher suites, and compression methods from the client and selects the best option.
  • Server Authentication: The server sends a digital certificate to the client, and the client verifies the certificate.
  • Key Exchange: After verification is complete, both parties exchnage information, such as the public key, to generate encryption keys for secure communication.
  • Session Key Generation: Both sides generate a unique session key for the communication session.
  • Secure Communication: When the handshake is complete, the communcation ensues encyrpted.
  • Connection Termination: If the TCP connection is closed, the TLS session is terminated without compromising the data.

What sets TLS above SSL?

TLS offers several improvements over SSL, making it vastly superior in terms of security and functionality. TLS uses Advanced Encryption Standard (AES), an ecryption algorithm used to secure data by converting it into an unreadable format without the correct encryption key (GeeksforGeeks). RSA and Diffie-Hellman are used to secure key exchange, while supporting hash functions and SHA-256 to protect data from unauthorized modification. These enchanced security features ensures data remains protected and private during transmission, while also preventing cyberattacks.

TLS also features a unique feature called Perfect Forward Secrecy (PFS), which ensures previously transmitted data remains secure even if the private key is compromised in the future (GeeksforGeeks). This process works by generating a unique session key for each communication session, which is not stored permannently and cannot be reused. PFS:

  • Generates unique session keys for each communication session
  • Does not store session keys permanently
  • Ensures data remains secure even if the private key is compromised
