Introduction

HTTP (Hypertext Transfer Protocol) is a group of stateless, application-level request/response protocols that share a basic interface, semantics, and messaging structure to enable interaction with network-based systems (Datatracker). HTTP does NOT encrypt information while the web browser and server communicate and share data. Like HTTPS, HTTP works by having one party send a request and the other send an HTTP response back.

HHTTPS (Hypertext Transfer Protocol Secure) is used to secure data while a web browser and website communicate. As the secured version of HTTP, its goal is to encrypt sensitive data while the browser and server communicate. This data can include login information, banking information, insurance details, and anything else you wouldn't want a stranger to know (Cloudflare). HTTPS uses TLS (Transport Layer Security), an encryption protocol, to secure communication.

Brief History of HTTP/HTTPS

  • 1990: HTTP was created as a building block of the World Wide Web alongside HTML. At this stage, HTTP could only perform a very simple task, GET, which required a path to the file being retrieved.
  • 1994: SSL (Secure Sockets Layer), which would later evolve into TLS (Transport Layer Security), was created to protect communication over the internet.
  • 1999: Over the course of five years, SSL evolved into TLS, becoming the standard security protocol for HTTPS.
  • Today: After countless tweaks and updates, HTTPS has become much stronger, faster, and more secure. It has also become far more accessible, allowing websites to adopt it much more easily.
