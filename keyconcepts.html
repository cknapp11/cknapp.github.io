HTTP

HTTP (Hypertext Transfer Protocol) is a group of stateless, application-level request/response protocols that share a basic interface, semantics, and messaging structure to enable interaction with network-based systems (Datatracker). HTTP does NOT encrypt information while the web browser and server communicate and share data. Like HTTPS, HTTP works by having one party send a request and the other send an HTTP response back.

HTTPS

HTTPS (Hypertext Transfer Protocol Secure) is an extension of HTTP that adds a layer of security through encryption. It uses SSL/TLS protocols to encrypt data transmitted between the web browser and server, ensuring that sensitive information remains confidential and protected from eavesdropping and tampering. This data can be log in information, banking information, insurance details, anything you wouldn't want a stranger to know

SSL Protocols

Secure Socket Layers (SSL) was developed in 1995 as an Internet security protocol that encrypts data to ensure secure communication between devices over a network, and is the direct predecessor to TLS (GeeksforGeeks). SSL uses 3 mechanisms to ensure secure communication: encryption, authentication, and integrity.

  • Encryption: prevents unautherized parties from reading the data being transmitted, presenting itself as jumbled letters and numbers.
  • Authentication: uses the handshake method to verify the identity of the parties involved in the communication. The handskae method follows 4 steps: the client and server exchange hello messages, the server sends its digital certificate and server key information to the client, the client verifies the certificate and responds with its own, and lastly, Change Cipher Spec secures the connection.
  • Integrity: detects any tampering during transmission.

The importance of SSL is that before its creation, web data was trasmitted in plain text, making it vulnerable to interception and manipulation by third parties. With the three mechanisms listed above, SSL ensures that data is encrypted, authenticated, and protected from tampering, providing a secure communication channel for sensitive information.

TLS Protocols

Transport Layer Security (TLS) is the successor to SSL, developed in 1999 to provide enhanced security at the transport layer. TLS uses similar mechanisms to SSL, including encryption, authentication, and integrity, but with improved algorithms and protocols. The handshake process that's used in SSL is also implemented into TLS, but with increased security measures. Some of these features are:

  • The use of Advanced Encryption Standard (AES), which provides stronger protection against attacks.
  • The use of Rivest-Shamir-Adleman (RSA) algorithm for secure key exchange, as well as Diffie-Hellman key exchange.
  • Supports hash functions.
  • Protects data from unauthorized modification.
  • Cyberattack prevention.

Public and Private Key Cryptography

HTTPS works by using an encryption protocol called TLS, or Transport Layer Security, to encrypt communication between server and web servers. This system uses two different keys for encryption: The private key and public key. The private key is the website owner's and exists on the web server for the purpose of decrypting information encrypted by the public key (CloudFlare). The public key, on the other hand, is available to everyone who interacts with the server, and can't be decrypted, other than by the private key.
