HTTP 1.0

HTTP/1.0 was severely limited, as initially, only HTML files could be retrieved using the “GET” command. Over time, content headers were implemented to allow the retrieval of other file types, making HTTP/1.0 more versatile through advancements in servers and browsers.

HTTP 1.1

Published in 1997, HTTP 1.1 was a huge improvement, with the following features (MDN):

  • Reusing connections, saving time.
  • Pipelining added as a feature, which allowed a second request to be sent before the first was finished, lowering latency.
  • Support for persistent connections.
  • Chunked transfer encoding.
  • Additional cache control mechanisms.

    • HTTP 2.0

    In the early 2010's, Google used an experimental protocol called SPDY, or “speedy”, which introduced an alternative way of exchanging data between client and server became the basis for HTTP/2. Published in 2015, HTTP 2.0 introduced several significant improvements over its predecessors:

  • Binary protocol instead of text-based, allowing for improved optimization.
  • Header compression to reduce overhead.
  • Multiplexing, allowing multiple requests and responses to be sent simultaneously over a single connection.
  • Server push capabilities.

    • HTTP 3.0

    HTTP/3 is the latest version of the protocol, which is based on QUIC (Quick UDP Internet Connections), a transport layer network protocol developed by Google. This is the biggest difference between HTTP/3 and HTTP/2, as HTTP/2 uses TCP (Transmission Control Protocol). This just means instead of one stream of bytes (TCP) which waits for missing packets, causing delays, QUIC uses multiple streams so that if one is lost, it keeps going. HTTP/3 aims to improve performance, security, and reliability compared to its predecessors.

    How Does HTTPS Work?

    HTTPS works by using an encryption protocol called TLS, or Transport Layer Security, to encrypt communication between server and web servers. This system uses two different keys for encryption: The private key and public key. The private key is the website owner's and exists on the web server for the purpose of decrypting information encrypted by the public key (CloudFlare). The public key, on the other hand, is available to everyone who interacts with the server, and can't be decrypted, other than by the private key.

    Private Key:

  • Used to decrypt information encrypted by the public key.
  • Exists on the web server.

    • Public Key:

  • Used to encrypt information.
  • Available to everyone who interacts with the server.

    • Why use HTTPS? Why is it Important?

    HTTPS actively prevents third parties from viewing information while the website and browser communicate. On regular HTTP, information is broken into packets, which are easily decrypted, and using mediums like public Wi-Fi also makes users highly vulnerable to interception (CloudFlare). With HTTPS, even when intercepted, the packets will be read back as incomprehensible, for example:

  • Username: guy123, Password: password123
  • Encrypted with HTTPS: g5K9xT3vL7Qp2mZ8nW4rA1fY6cJ0uH3sE9bN5dP2kR8=
